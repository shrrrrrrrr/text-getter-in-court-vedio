# 校园 Web 部署规格：ASR 短测通过后的下一阶段

本文件是后续开发的规格，不是已实现功能或已部署声明。服务器离线 ASR 环境与英文控制录音 GPU 短测试已由用户回传确认通过；无需重复下载、上传模型或重建准备环境。真实配置及报告只保存在忽略目录。

目标是在用户指定的校园网地址和端口提供上传、转写、校对和 Markdown 导出。保持现有 GLM 服务，使用已校验的 ASR 权重；不接入公网法律站、SimCourt 或 GLM，不自动修改防火墙及其他已有服务。

## 已确认的工程缺口

- Web 项目声明 Python 3.11–3.13，而已准备 ASR 环境的 ABI 是 Python 3.10。不能直接认定两者兼容。应在隔离环境验证 Web 对目标版本的支持，或提供独立的受支持 Web 运行时；保留已通过的 ASR 环境。
- 应用当前仅信任本机 Host，启动入口默认监听回环地址。校园服务需要显式的监听配置和精确 Host 白名单；不要用放开全部 Host 替代配置，也不要把本机地址当成校园可达性证据。
- 当前任务列表、编辑、导出、媒体和抽帧接口没有用户归属检查。多人版本需先确定访问凭证及任务所有权，在服务端覆盖全部任务入口；猜到任务 ID 也不能访问他人的内容。未满足前不宣称支持校园多人使用。
- 当前 `Runner` 的 `LocalEngine` 缓存模型，Web 常驻后可能持续占用 GPU。短测试采用独立进程，不能据其退出后的显存释放宣称网页会自动释放。若采用逐任务子进程释放 CUDA，应验证排队、取消、进程归属及异常恢复，不能影响 GLM。
- 已准备的是 ASR 依赖，不是完整 Web/FFmpeg 运行环境。需核对 Web wheel、`ffmpeg` 和 `ffprobe`；缺失依赖继续走本机正常 TLS 和来源摘要校验、完整离线包及已验证的普通 SSH 传输路线，不回退到服务器在线下载。

## 验收条件

1. 离线安装可复用原权重和缓存；仅创建可识别归属的应用目录和服务，失败保留证据，恢复路径明确。
2. 用户登录或会话凭证、任务列表、上传、编辑、取消、重试、媒体、抽帧和所有导出都经过归属检查；跨用户及跨站访问测试通过。
3. 先以回环地址完成真实媒体上传、规范化、GPU ASR、状态查询和 Markdown 导出的端到端测试，再按明确校园地址/端口启动并从校园另一台设备验证。
4. 正常任务完成、失败及取消后均检查自有 worker 和 GPU 资源；单任务、长音频及排队行为单独记录，指定 GPU 不能视为显存硬配额。
5. 文案按实际部署位置说明文件在服务器处理，不继续声称“文件留在本机”；使用引导明确访问凭证、任务可见性和未验收能力。
6. 英文工程控制录音不作为中文庭审准确率、角色识别或多人重叠的效果证据。真实授权素材、标注和核听验收另行进行。

交付仍以减少人工步骤为原则：本机生成并校验一次应用包，服务器一段命令顺序完成安装、环境检查和本机端到端验收；校园监听按明确配置启用。不要让用户重复此前已经通过的 ASR 准备步骤。
