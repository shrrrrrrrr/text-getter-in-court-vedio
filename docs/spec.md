# 首版规格与验收边界

目标：仅从庭审视频/音轨建立按时间顺序、可逐句核听、可审计修改的逐字稿，禁止总结、修饰和凭空补全。部署到法律站留到独立阶段。

## 处理流程

上传（UUID 私有目录、大小上限、输入 hash）→ ffprobe 检查 → 选定音轨/16 kHz PCM → ASR 原始结果 → 说话人时间轴 → 逐词归属/重叠区间 → 可选重叠分离再识别 → 自述角色候选 → 可选本地文本/视觉角色 Agent → 人工校对 → Markdown/JSON/审计导出。

FastAPI 服务端 + 无构建依赖的浏览器前端，单个推理 worker、最多 8 个在队列/执行中的任务。任务状态落盘，重启不自动重提云端任务。校对使用乐观版本锁；冲突返回 409，不覆盖输入。所有法律身份默认未确认。

## 可以检验的工程标准

- 上传真实可解码容器，识别所选音轨；无音轨、坏文件、不支持编码、过大/过长、音轨不存在均清楚失败。
- 不以演示文本、语言模型猜测或复制重叠句子伪装识别结果。
- 原始 ASR 结果与人工校对内容分开；语气词/重复不由应用过滤；不保证 ASR 模型绝不遗漏、规整数字或产生错词。
- 每个观察到的词只归属一个声音；另一个没有恢复的重叠声部保留占位。
- 角色建议引用已存在且属于该声音的原文片段；角色确认必须有人工证据；能新增人物、重分配片段、填写自定义角色。
- 发言按开始时间排序，同时发言保留各自时间；导出仍显示所有未完成的核听项。
- 运行记录包含输入/音轨 hash、软件版本、模型和解码参数、音轨、说话人人数参数、管线版本、耗时与阶段；未固定模型 revision 时明确标记，固定本地 ASR 目录可保存文件指纹。
- 桌面优先分区滚动，窄屏自然堆叠；长结果不裁掉。支持键盘、对话框、减少运动、字体本地加载、加载/失败/空/中断状态。

## 尚不能据工程通过宣称的目标

- 中文庭审逐字准确率、语气词完整性、方言、远场、录音回声和专名准确性。
- 全庭人员数、跨长视频稳定身份、无自述角色的自动识别、音画同步说话人定位。
- 双人分离模型在中文庭审的泛化；三人以上重叠、极低信噪比完整恢复。
- 自动形成法院认可的正式庭审笔录，或满足证据保全/身份认证要求。

这些目标需要真实授权样本、专家标注、实模和人工效果对照。界面、适配器、规则或单元测试不能代替效果证据。

## 建议的效果验收集

先收集 10–20 段已授权、脱敏的 1–3 分钟视频，包括清晰单人、双人轮替、双人重叠、三人重叠、回声、低音量、方言、远端连线、桌牌可见/不可见、角色自述/无自述。按视频划分开发/验证/隐藏测试，同庭不跨分区，标注真实说话人、逐字文本、起止时间、重叠与听不清。

分别测量 CER、语气词/重复召回、说话人 DER/JER（含/不含重叠分别报告）、有人工映射的说话人文本错误率、角色候选 precision/recall、确认/升级覆盖率、重叠每个声部的文本召回、耗时、内存/显存与人工复核时间。不以“输出更通顺”作为原话质量指标。门槛先由法学团队和任务实际用途确认，不捏造一个已经达到的百分比。

可直接向法学团队提问：

> 我们只从庭审视频生成逐字转写辅助稿，请提供一个法域与案件类型的角色列表，并确认：语气词、口误、重复、打断如何标注；多人同时发言如何排列；无自我介绍时哪些画面/称呼可作为角色候选，哪些必须人工确认；“听不清”的允许标法；可用视频与脱敏范围；辅助稿与正式庭审笔录的用途边界。请分别标记确定要求、争议点和待查事项，并提供 10–20 段可标注样本。

角色词表是界面选项，不是关于特定法域诉讼制度的法律判断。陪审团成员、人民陪审员、公证人等不能不加区分地视为每场庭审都有的角色。
